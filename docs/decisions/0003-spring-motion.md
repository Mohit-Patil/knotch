# Spring motion for the notch terminal

The owner requested a smoother, bouncy reveal after the notch-placement and automatic-minimise correction. The native AppKit panel now opens with a SwiftUI Spring curve driven by NSView's display link. Its actual window frame grows from the notch lip and settles with a small overshoot. Closing retracts with a critically damped spring. Interruptions retain current position and velocity; cancelled completion callbacks cannot hide a reopened panel.

The terminal host keeps its full resting size throughout. Only the window clipping rectangle changes, avoiding text scaling, PTY grid churn, and an invisible full-size mouse target. The same Ghostty surface and shell remain alive. Closing releases keyboard focus immediately and disables panel hit testing, then orders the window out when motion finishes. Display links stop when idle. Screen lock/sleep events finish hiding immediately, including during an existing retraction.

Opening settles at 580 ms; closing at 340 ms. This deliberately supersedes the handoff's shorter default transition in response to the owner's bounce request. It is not a measured latency or frame-pacing claim. Reduce Motion uses a 120 ms opacity transition at fixed geometry, without bounce. Display/accessibility changes cancel the current motion safely.

Validation: Release and test builds, model tests, and 21 native overlay checks passed. New native checks observe intermediate window geometry with unchanged terminal view size and Ghostty rows/columns, interrupted close/reopen, immediate lock-event hiding, and fixed geometry under a test-only Reduce Motion override. Existing focus, typing grace, interaction lock, auto-minimise, and retained-session checks also pass. The fixture supplies pointer and lock events and overrides Reduce Motion; it does not qualify physical hover, OS lock delivery, user-perceived smoothness, or frame pacing. Full engine harness results remain historical; that suite was not repeated for this presentation change.

The shipping build was produced successfully. The owner's existing app had an active shell, so it was left running and returned to its collapsed state. The new motion takes effect on the next app restart; sessions do not survive quitting.
