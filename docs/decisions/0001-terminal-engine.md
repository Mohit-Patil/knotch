# ADR 0001: Embed the pinned full Ghostty core

Status: accepted for the native harness, September 25, 2026.

Knotch needs a real PTY terminal with Ghostty's native rendering and input behavior. We use the full macOS `GhosttyKit` static XCFramework generated by Ghostty at commit `982fe90d941e4b4aab4905ffcbcfdea60bd83343`. `libghostty-vt` only supplies virtual-terminal facilities and is not a complete embeddable native terminal view. The revision, source archive digest, toolchain, build flags, and notice live in `ThirdParty/dependency-lock.json`.

The current `include/ghostty.h` is Ghostty's internal embedder interface, not a stable public SDK. Knotch keeps calls behind a local adapter; any Ghostty upgrade must recheck that header, the native lifecycle, input/clipboard callbacks, the static link, and the resources before changing the pin. No source patches are used in this checkpoint.

`scripts/bootstrap-engine.sh --build` fetches the exact revision, downloads declared remote dependency archives over IPv4 with bounded timeouts, verifies their manifest hashes through Zig, and builds the native arm64 framework with Zig 0.16.0. It uses Zig's default global cache unless `ZIG_GLOBAL_CACHE_DIR` is supplied; downloaded archives remain in the project's ignored `.build/dependency-archives`. `scripts/build.sh` requires that artifact and stages `zig-out/share/ghostty` and `zig-out/share/terminfo` as sibling folders inside Knotch's own `Contents/Resources`, matching Ghostty's macOS resource discovery. The copied MIT notice and engine revision remain in the app bundle. The app does not depend on a separately installed Ghostty.app.

This choice requires compiling a large upstream core and maintaining an integration against an internal interface. A successful local build and runtime acceptance results, rather than this decision alone, determine whether the integration is viable.
