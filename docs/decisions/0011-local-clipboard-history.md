# Local clipboard history inside Knotch

The owner explicitly expanded the personal app to include a clipboard for text, images, links, and files, with history kept locally until cleared. This is a separate in-panel Clipboard tab, not a replacement for the Ghostty terminal's Command-C/Command-V or its OSC clipboard consent flow.

Knotch observes `NSPasteboard.general.changeCount` every half-second while running. It records new plain text, HTTP(S) links, plain-plus-RTF, PNG/TIFF images, and file URLs. No Accessibility, Input Monitoring, Screen Recording, or global keyboard capture is used. It skips pasteboard items with concealed, transient, or autogenerated markers, refuses empty or oversized entries, deduplicates repeated copies, and keeps at most 50 entries. The tab offers search, previews, copy-back, pin, delete, pause, and clear. Copy-back updates the observed change count so it does not insert a duplicate. File entries contain paths, not file data, and Copy restores file URL representations. These bounded types are the first version of “more things”; unsupported pasteboard types are omitted rather than serialized blindly.

The default is local persistence across app restarts, as the owner chose. History is encoded in the bundle-specific Application Support directory, which is set to owner-only permissions (directory `0700`, file `0600`). The Settings toggle turns persistence off and removes the history file; pausing skips content copied while paused. Clearing history does not overwrite the current system pasteboard. Knotch itself makes no network request with this data. Local files are not encrypted separately, so someone with access to the user's unlocked account or backups may be able to read them. Password managers' concealed/transient markers are respected, but not every source labels secrets. The user can pause, clear, or disable disk persistence.

Native fixture tests use a uniquely named pasteboard and synthetic content, never the owner's clipboard. The focused clipboard fixture checks capture and restoration of text, links, RTF, image, and file URLs; concealed exclusion; pause; local reload; pin/clear; disk opt-out; and retention of a real Ghostty shell while the tab is selected. Visual inspection of an isolated signed app confirmed the empty Clipboard and Settings surfaces. It did not inspect or log the owner's clipboard contents.
