# External screenshots dropped on the notch

The owner found that dragging a screenshot from macOS to the notch did nothing. The previous drop implementation accepted only Knotch's private Clipboard-tab entry ID, so native screenshot and Finder drags were not recognized by the notch handle or terminal.

The handle, expanded panel, and Ghostty surface now register for native file URLs, PNG/TIFF image data, and `NSFilePromiseReceiver.readableDraggedTypes`. Hovering with one of those drags opens and activates the existing spring-driven panel. A short presentation lock spans the transition from handle to expanded panel. Dropping a supported image saves it in Knotch's local Clipboard history and inserts an owner-only temporary image path through Ghostty's text/paste API, without Return. Single image files are copied into history rather than retaining a potentially short-lived screenshot path. Ordinary files retain URL references and insert escaped paths. If there is no running session, the drop opens a home shell.

The shared drop destination described above was superseded after the owner found that a notch drop unexpectedly opened a shell and displayed its PNG path. The notch handle and panel background now save to Clipboard and select the image carousel without terminal insertion or shell creation. Only a drop on a terminal tab or Ghostty surface inserts the private path. External drag hover over a terminal tab selects that session.

AppKit file promises are received asynchronously into an owner-only temporary directory, read as an image, and removed on normal app quit. A synthetic named pasteboard can verify recognition of a promise, but does not fulfill it without a live AppKit drag session. The native fixture verifies direct-image and file-URL delivery to a real Ghostty shell, and the overlay reveal state. A physical floating-thumbnail drag remains to be qualified on a Mac; success for that gesture is not inferred from the fixture.
