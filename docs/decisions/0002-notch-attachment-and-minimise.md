# Notch attachment and automatic minimising

The owner screenshot showed a real placement bug: the former 160×28 labeled pill was clamped below the menu bar, with the terminal stacked underneath. On September 25, 2026 the owner requested a shape joined to the notch and explicitly chose automatic minimising after clicking too, except while typing, selecting or using a dialog. This overrides the original PRD rule that keyboard focus alone holds the panel open. Original handoff documents remain unchanged.

The corrected layout uses the gap between NSScreen auxiliary top areas. On the owner's live display (1710×1112 points, 2× backing scale), the camera exclusion is `(751,1074,209,38)`. The collapsed cap is `(743,1065,225,47)`: it reaches the physical screen top and adds 8-point side wings and a small lower lip. The terminal body is `(375,553,960,520)`, ending at the usable top y=1073 and overlapping the lip. The notch cap alone uses status-bar window level and permits placement at the screen edge; the large terminal stays below the menu bar at floating level. A black cap and black panel remove the visible seam. No text or controls are placed under the camera. Plain displays retain a top-center pill.

Launch is collapsed with no activation or shell creation. Hover still reveals a nonactivating preview. Leaving both the cap and panel schedules minimising after 350 ms. Actual terminal input renews a 1.5-second inactivity grace; selection, composition, pending clipboard confirmation, file pickers, quit/close dialogs and settings hold presentation. Reentry cancels stale timers. Reactivation while a dialog lock remains held preserves the recorded pointer exit, so closing the dialog can complete minimising. A shortcut-only activation does not arm auto-collapse until the pointer actually enters and leaves. Minimising changes presentation/occlusion only, preserving the same Ghostty surface and shell. A timed collapse can restore the former application only while Knotch still owns keyboard focus and remains active; a stale callback cannot pull focus from a third app.

The model suite covers exact live geometry, negative origins, invalid auxiliary regions, plain screens, auto-hidden menu bars, tiny frames, typing renewal, stale timers, reentry, locks and keyboard-only activation. The revised native controller suite passed 17 checks including actual AppKit window frames, auto-minimise with the same shell/surface, input postponement and interaction locks. It supplies a complete pointer event sequence, suppressing unrelated hardware pointer tracking only in this fixture so an owner's pointer over the test window cannot contaminate the trace. The shipping build always uses native tracking. These are native controller tests, not physical mouse qualification.

Two intermediate fixture runs failed because the live pointer entered a window opened beneath it while the fixture was also supplying pointer exits. State diagnostics showed `pointerInPanel=true`, correctly preventing collapse; isolating the fixture's event source made its trace deterministic. The final shipped input/tracking path does not disable these real events. Physical cross-app pointer and global shortcut qualification remains outstanding.

The exact upstream engine pin and resource layout are unchanged.
