# Settings tab and display fit

The owner requested that Settings live inside the expanded notch panel, then showed the compact handle sitting beneath the menu bar on a plain 3840×2160 external monitor. These requests refine the earlier alpha placement and settings-window choices.

Settings is now a persistent tab in the same horizontal strip as terminal sessions. It hosts the hover switch and shortcut recorder in the existing panel. Selecting it detaches the selected Ghostty view without closing the surface or PTY; returning to a terminal tab reattaches the same view. The Settings tab has no rename or close actions. Shortcut recording holds the panel open while active. Menu and header actions open that tab instead of creating another settings window.

On a display with a measured camera housing, placement still uses AppKit's `auxiliaryTopLeftArea` and `auxiliaryTopRightArea`. On a plain display, the collapsed handle is anchored to `NSScreen.frame.maxY` in the measured menu-bar band rather than drawn over app content below `visibleFrame.maxY`. The expanded panel reaches the same top edge, while horizontal and lower bounds continue to respect `visibleFrame`. Its preferred 960×520-point size grows to at most 1280×720 points on large displays and shrinks to fit small ones. Current screen geometry is recomputed on display-parameter notifications; no pixel resolution is hard-coded. Terminal font size remains governed by the user's Ghostty configuration.

This specialized overlay intentionally draws in the menu-bar band. Ordinary application content follows Apple's [visible-frame guidance](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe); Apple says that value changes with current UI settings and should not be cached. The camera housing itself is derived from Apple's [auxiliary screen areas](https://developer.apple.com/documentation/appkit/nsscreen/auxiliarytopleftarea-uglc?language=swift), while critical text remains outside it, consistent with [macOS layout guidance](https://developer.apple.com/design/human-interface-guidelines/layout).

`scripts/test-models.sh` exercises screen geometry, including the connected 3840×2160 shape, and `scripts/test-native.sh settings` checks actual native-window placement plus session identity and output while Settings is selected. This is not physical multi-display, Spaces, or hover qualification. The final direct-executable full overlay fixture stopped before its focus check because its visible editor window did not become foreground; an earlier Launch Services attempt passed focus but timed out later in raw-input output. Neither result qualifies the complete overlay suite for this change. The focused Settings fixture is the current evidence for the new behavior.
